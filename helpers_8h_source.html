113// -----------------------------------------------------------------------
114// Temporary arrays: why and how we avoid them
115//
116// A JEM array (Vector, Matrix, Cubix) is a small handle that points to a
117// block of numbers. Copying a handle ("Vector a = b;") is cheap and does NOT
118// copy the numbers: a and b then show the same numbers. Creating a new array,
119// or writing "x = matmul(A, v)", asks the memory manager for a fresh block of
120// numbers and gives it back afterwards. For the 3 to 6 numbers of a rod
121// element this bookkeeping costs more than the arithmetic itself, and in the
122// force assembly it happens millions of times per run. Therefore the code that
123// is executed for every element and every time step ("hot code") follows
124// three rules; everywhere else (set-up, output, rarely used code) the short
125// forms matmul(A, v) and skew(v) stay, because they are easier to read.
126//
127// 1. Work arrays: arrays that live as (mutable) members of the class, are
128// created once in the constructor/configure and overwritten in every
129// call. A work array is always written completely before it is read
130// within the same call, and it is never used to carry values from one
131// call to the next. A class with work arrays must not be used by several
132// threads at once.
133// 2. 3 x 3 products: mul3(C, A, B) and mul3(y, A, x). The result may be one
134// of the factors.
135// 3. All other matrix products: a MatmulChain member (jem::numeric), which
136// keeps its result array and reuses it. The result is only valid until
137// the next call of the same chain, so use it directly or copy it first.
138// -----------------------------------------------------------------------
